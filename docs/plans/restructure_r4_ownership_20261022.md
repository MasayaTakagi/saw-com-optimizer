Do not add a comparator to `evaluation.py`, change its tuples, or move design/evaluation policy into the optimizer. Do not add import-proxy packages or old-checkpoint readers.

## Numerical reproducibility investigation and CI containment

**Diagnosis:** the exact-hash discrepancy is induced by automatic OpenBLAS CPU-kernel dispatch, not R4 source relocation, test nondeterminism, thread count, or a changed input. On the same fixed inputs, OpenBLAS `SkylakeX` and `Haswell` dispatch paths produce repeatable, slightly different IEEE-754 results. The test-only CI fix pins the existing full suite to `OPENBLAS_CORETYPE=Haswell`, matching the frozen exact hashes. It does not change production/runtime settings, equations, tolerances, expected hashes, feasibility/rank policy, or optimizer behavior.

- New fixed-input diagnostic: `tools/diagnostics/evaluation_repro.py`. It logs Python/NumPy/SciPy/OpenBLAS runtime, runner/CPU flags and image, input/config/grid identities, exact hashes, Y/S/GT metadata, per-component absolute/relative/ULP deltas, same-process and independent-process repeats, single-thread comparison, physical diagnostics and feasibility-first rank inputs. It uses only the existing hypothetical fixed regression cases; scratch arrays are confined to an automatically deleted temporary directory. CI adds the locked `benchmark` extra solely for `threadpoolctl`; the single full-pytest job is retained.
- Local comparison on identical locked Python 3.12.3 / NumPy 2.5.3 / SciPy 1.18.1 / OpenBLAS 0.3.34.106.0 inputs showed exact equality between R3 baseline `81d18ba3bd3e29b13958d4b32dfec5585ab9d947` and PR code: all frozen filter Y/S/GT, T1 Y, and T2 Y hashes matched; separate default processes, in-process repeats, and single-thread BLAS also had zero differing components. The local runtime selected OpenBLAS `Haswell`.
- Diagnostic/full-suite CI run `39815480835` (head `2b037530178b19008ba9a49dbae8e69709a5171a`) reproduced the failures on Ubuntu 24.04.5 / image `20261012.334.1`, AMD EPYC 9V74, AVX-512-capable flags, OpenBLAS `SkylakeX` 0.3.34.106.0. Automatic (4-thread) and forced single-thread processes produced identical hashes, and two independent default processes plus repeated in-process evaluations had zero differing components. Thus thread count was not the cause. The observed filter Y/T1 Y hashes were the previously reported `43271d…` / `31a09b…`; the diagnostic also recorded filter S `246b2f…`, filter GT `941a4a…`, and T2 Y `c6bdf1…`.
- On the later Intel Xeon 6973P-C runner, automatic `SkylakeX` dispatch again produced those alternative hashes; with only `OPENBLAS_CORETYPE=Haswell` changed before imports, all five exact regression hashes matched their frozen values. Across auto-vs-Haswell arrays, observed maximum absolute / scaled-relative / ULP differences were: filter Y `5.56e-17 / 1.22e-13 / 993` (2,249 real/imag components across 1,614 complex cells); filter S `4.45e-16 / 7.36e-12 / 40,941` (3,998 components, 2,807 complex cells); filter GT `6.11e-16 / 2.51e-15 / 20` (479 values); T1 Y `2.39e-18 / 3.49e-15 / 16` (19 components); T2 Y `3.47e-18 / 5.93e-16 / 4` (11 components). First differing entries were reported by the diagnostic. These are dispatch-path numerical differences, not array nondeterminism.
- Physical/ranking checks across the two kernels: all response values remained finite; filter minimum conductance eigenvalue stayed `3.2952807162421596e-7` (passivity tolerance `1.01e-8`); filter relative solve residual was `3.92e-17` vs `4.16e-17`; maximum condition number `21.927466872323965` vs `21.927466872323947`; reciprocity residual `1.37e-16` vs `1.46e-16`. `GT`–`|S21|²` maximum discrepancy remained below `2.8e-16` for filter/T1/T2. Every reported metric, violation, feasibility value, scalar search objective, and `FeasibilityFirstComparator` rank key was exactly equal between kernels. No feasibility or rank change was observed; no scientific acceptance criterion was adjusted.
- CI containment is scoped only to the existing full test command in `.github/workflows/ci.yml`; the preceding diagnostic still captures automatic dispatch and explicitly compares it to Haswell. The full suite passed **572 passed / 1 skipped** on final head `12729c2ed20cf7389b64e8c88901bfd709dec433` in two independent clean runs (`39817407112`, attempts 1 and 2), on Intel Xeon 6973P-C and AMD EPYC 9V45 runners, both of which selected automatic `SkylakeX` and therefore directly exercised the pinned-Haswell correction.
