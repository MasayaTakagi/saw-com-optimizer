# Architecture overview

## Package responsibilities

- `core/` implements COM sections, acoustic and electrical networks, S-parameter
  conversion, metrics, and physical material calculations.
- `problem/` defines reusable design spaces and evaluation boundaries,
  including the canonical DMS topologies in `dms_topologies.py` and the released
  DMS representation in `released_dms.py`.
- `optimizers/` contains backend contracts, L-SHADE, the SciPy differential
  evolution backend, candidate comparators, and optimizer-generic polish.
- `optimization/` contains SAW search orchestration and shared services such as
  accounting, adaptive frequency handling, budgets, caching, convergence
  evidence, counters, history, population management, the runner, and
  SAW-specific mixed-variable polish.
- `studies/` contains live role-named study adapters plus historical/read-only
  audits. Stage-specific adapters may remain for qualified historical workflows,
  but reusable logic should move into role-based modules rather than multiply
  Stage-specific copies.
- `io/` owns configuration resolution, persistence, checkpoint lifecycle, and
  provenance.
- `reporting/` builds compact review artifacts and historical/ad-hoc bundles
  from saved runs; it does not own production raw storage.
- `orchestration/` owns detached production launch, exact-thread queue
  continuation, active-run coordination, persistent-run validation, and review
  publication state.
- `runtime/` configures execution environment boundaries.

Study adapters compose problem definitions, optimizer backends, and optimization
services. Production orchestration freezes the exact source/config/protocol
identity before detached execution.

## Persistent run storage

New user-authorized or ranking-eligible production raw data lives outside every
Git worktree under an explicitly supplied absolute persistent root/path.
The active storage policy is `external_persistent_v1`.

The external raw run owns checkpoints, populations, dense arrays, full process
logs, continuation/recovery state, and terminal raw numerical artifacts.
The Git repository owns source/config/protocol plus compact review evidence and
decision history.

See
[`guides/data_storage_logging_review_policy.md`](guides/data_storage_logging_review_policy.md)
and [`guides/worktree_safety.md`](guides/worktree_safety.md).

## Provenance

`sawopt.io.run_store.initialize` supports the historical schema-v1 fingerprint
contract. New studies may use
`sawopt.io.provenance.build_fingerprint_metadata` to save schema v2 with two
hashes:

- `computation_fingerprint`: canonical configuration plus an explicit list of
  source dependencies that can affect numerical results.
- `reporting_fingerprint`: an explicit list of report, plotting, review-spec,
  and export dependencies.

Both lists are recorded with file hashes in `dependency_manifest`. A source file
must be listed in exactly one set. Production computation gates compare the
computation fingerprint; a reporting-only change leaves that gate valid and can
trigger review-artifact regeneration. A v1 fingerprint remains readable but is
never interpreted as a v2 computation fingerprint.

## Production review export

The canonical new-production review path is generated by the generic
`export-review` flow and committed under:

```text
reports/experiment_reviews/<stage>/<run_id>/
```

It contains compact manifests, config/protocol snapshots, terminal result/status
coverage, convergence/boundary/runtime summaries, integrity evidence, and
scientific limitations. Large raw checkpoints, populations, dense arrays, and
full process logs stay in external persistent storage.

The package-level contract is in
[`guides/postrun_review_contract.md`](guides/postrun_review_contract.md).

## Historical/ad-hoc review bundles

`sawopt.reporting.review_bundle` and `ReviewBundleSpec` remain available for
historical/ad-hoc ZIP packaging of saved runs. They are not the canonical
publication path for new production studies.

Standalone legacy/manual bundle instructions are in
[`guides/review_bundles.md`](guides/review_bundles.md).
New experiment guidance is in
[`guides/new_experiments.md`](guides/new_experiments.md).
