## 1. R6 boundaries and required evidence

R6 may add a small `sawopt.cli` composition boundary and a smallest config → design → injected response/metrics → optimizer strategy → R5 external run store → review-schema-v1 export path using a synthetic fixture only. It must not import or call COM/FE. The source SHA used in a synthetic fixture is an explicitly injected test identity, never a scientific execution claim. The synthetic smoke must record exact config/model/search-domain/validation-set hashes, every expected cell (including failures or unrun cells), observed search and validation accounting separately, and only observed convergence checkpoints. A successful synthetic output remains synthetic and has no scientific or Q1 qualification status.

R5's `sawopt.io.experiment_store` and `sawopt.reporting.experiment_review` contracts are implemented in PR #70 and are future-only. Use isolated temporary external data roots and temporary mock repositories in tests; never use repository-local `runs/` or a personal hard-coded path. Preserve R5 no-follow/collision/crash-fail-closed/redaction/10 MiB tests. **R5's descriptor-relative access and hash checks do not protect the raw tree against non-cooperating concurrent writers during review export**; the integration must document this limitation and not claim stronger concurrency safety.

The existing `python -m sawopt --help` shows the legacy commands `simulate`, `optimize`, `sweep`, `report`, `run-study`, `stage4b-shakedown`, and `export-review`, with legacy config/run defaults and conditional stage dispatch. This is not yet the R6 CLI. Help/import must have no execution side effects; no `./runs` fallback, hidden follow-up job, agent session or auto-launch is acceptable in the new entry point.

## 5. Observed import/dispatch and deletion hazards

- The old CLI imports run-lifecycle, optimizer-runner and reporting at module import; help output is evidence of the current legacy command set, not the R6 design.
- Study selection is runtime-config-driven via `study.type`, so a static import scan alone is insufficient to establish dead code.
- `problem.evaluator.dense` remains a direct optimizer-runner dependency. `core.hybrid.response` has a live `studies.hybrid` caller and direct test. R5 review export shares the `reporting/` package with legacy modules. These make blanket deletion unsafe.
- Orchestration is not synonymous with Codex: it also implements process supervision, status/recovery, run safety and worktree safety. Only its agent/session responsibilities are obvious cleanup candidates; other live behavior needs explicit successor/disposition.
- Existing tests under `tests/unit/orchestration/`, `tests/unit/studies/`, `tests/unit/reporting/`, and legacy `io` suites pin real behavior. Retire or replace tests only with the corresponding behavior decision, not just to remove import references.
- Old C2C/Codex and handoff documentation is not current policy; however active tests and links still refer to parts. Treat content as historical until those test/reference dispositions are reviewed, not as runtime authorization.
